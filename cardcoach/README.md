# 내 지갑 카드 코치 — ① 가맹점 인식 + ② 최대 혜택 추천 + ③ 실적 관리

사진 한 장(+GPS) → 브랜드 인식 → 내 카드(우리카드 앱에 등록된 것으로 가정, 시드) 중 결제금액이 가장 적은 카드 추천, 이번 달 실적이 급한 카드 코칭.

## 실행

### 백엔드 (FastAPI + SQLite)
```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```
- 첫 실행 시 `cardcoach.db` 자동 생성 + 시드(페르소나 지갑 카드 3장 · 매장 브랜드 124개 · 이번 달 사용 내역). 시드 수정은 `app/seed.py`에서.
- 모델에 테이블·컬럼이 추가되거나 `seed.py`의 `SEED_VERSION`이 바뀌면 예전 db는 시작할 때 자동으로 지우고 다시 만든다(인식·결제 기록도 초기화). 시드를 고치면 `SEED_VERSION`만 바꾸면 된다.

### 데이터 구조: 카드 상품 DB × 업종코드 × 내 지갑
```
data/benefits/            카드 상품 DB (읽기 전용 파일, app/catalog.py)
  cards/*.json            인기 카드 100장의 실제 혜택 639건 (적용 대상은 원문 그대로)
  taxonomy.json           업종코드 55개 — 카드 혜택에서 거꾸로 뽑음 (예: FD-CAFE 카페·커피전문점, RT-CVS 편의점, TR-FUEL 주유소)
  mapping.json            가게 → 업종코드 (브랜드 별칭 196개, 카카오 업종, Vision 라벨), 혜택 → 업종코드
  report.md               분석 리포트 (선정 방법, 업종 분류 판단, 시드와 공식 데이터 차이)
backend cardcoach.db      바뀌는 것만: 가게(브랜드·업종코드), 내 지갑(가진 카드 + 실적), 인식·결제 기록

추천 = 이 가게의 브랜드·업종코드 × 내 지갑 카드들의 혜택만 골라서 계산 (app/engine.py, AI 없이 규칙으로)
```
- 카드를 늘리려면 `data/benefits/cards/`에 파일만 추가 (코드 수정 없음). `GET /catalog` 로 상품 DB 요약.
- 내 지갑을 바꾸려면 `seed.py`의 `WALLET` (카드 상품 id, 지난달·이번 달 실적, 택1 혜택 중 안 고른 것) + `SEED_VERSION` 변경.
- 엔진이 계산 못 하는 혜택(마일리지, 리터당 할인, 실적 달성 보너스)은 할인 0원 + "자동 계산 불가 · 약관 확인"으로 표시하고 추천에서 빠짐.
- Swagger: http://localhost:8000/docs

### 프론트 (React + Vite, 모바일 웹)
```bash
cd frontend
npm install
npm run dev          # https://localhost:5173 (certs/ 가 없으면 http)
```
- 폰 시연: PC와 같은 와이파이에서 `https://<PC IP>:5173` 접속(터미널의 Network 주소). 백엔드는 위 명령 그대로(`--host` 불필요).
- 프론트는 백엔드를 `/api/...`로 부르고 `vite.config.js` 프록시가 PC의 8000번으로 전달한다. 그래서 https 페이지에서도 백엔드 호출이 막히지 않고, IP가 바뀌어도 `.env` 수정 불필요.
- **https가 필요한 이유**: 앱 안 카메라와 폰의 실제 GPS는 브라우저가 https(또는 localhost)에서만 허용한다.
- 인증서는 자체 서명이라 기기마다 처음 접속할 때 "비공개 연결이 아님" 경고가 뜬다 → '고급 → 계속 진행'. 발표 전에 시연 폰에서 미리 한 번 해 둘 것.
- 인증서 만들기(처음 받은 팀원만, Git Bash에서):
  ```bash
  cd frontend && mkdir -p certs && openssl req -x509 -newkey rsa:2048 -nodes -days 365 \
    -keyout certs/dev-key.pem -out certs/dev-cert.pem -subj "/CN=cardcoach-dev" \
    -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
  ```
  `certs/`는 `.gitignore`에 있어 GitHub에 올라가지 않는다.

## 인식 모드
| 모드 | 조건 | 동작 |
|---|---|---|
| mock (기본) | Vision 키 없음 | 업로드 파일명을 OCR 텍스트·사진 라벨로 취급. `starbucks.jpg` → 로고 인식 성공, `burger.jpg`/`coffee.jpg` → 사진으로 업종 추정, 아무것도 없으면 버거 사진 시나리오. 시연 플랜 B |
| vision | `backend/.env`의 `GOOGLE_VISION_API_KEY` (또는 `GOOGLE_APPLICATION_CREDENTIALS`) | Google Vision 로고 감지 + OCR + 라벨(사물) 감지 → 브랜드 별칭·업종코드(`mapping.json`)와 매칭 |

Vision 키 발급: GCP 콘솔 → Cloud Vision API 사용 설정 → 사용자 인증 정보 → API 키 (Cloud Vision API만 허용) → `backend/.env`. 조직 정책으로 서비스 계정 키(JSON)가 막혀 있으면 API 키 방식을 쓴다.
강제로 mock 쓰려면 `RECOG_MODE=mock`.

인식 근거(`source`)와 신뢰도
| 근거 | 신뢰도 | 설명 |
|---|---|---|
| `logo` | Vision score | 로고 감지 |
| `text` | 0.75 | 간판 글씨(OCR)에 alias 포함. 영문 alias는 단어 단위로만 매칭(`cu`가 `security`에 안 걸림) |
| `image` | 0.55 | 로고·글씨가 없을 때 사진 속 사물(버거, 커피…)로 업종 추정 → 근처 매장을 알면 **그 안의** 같은 업종 매장만, 모르면 등록 브랜드 중 같은 업종. 'fast food'처럼 넓은 라벨은 과자에도 붙어서 쓰지 않음 |
| `gps` | 0.50 | 위 근거가 약할 때 반경 50m 안 매장을 후보로 추가 ("근처 '카페 오로르'가 맞나요?") |
| `ai` | Claude 판단 | 0.80 미만으로 애매할 때만 Claude에게 사진 + 후보 매장 목록을 보내 하나를 고르게 함 (`ai_reason`에 이유). '맞는 매장 없음'이면 gps 후보를 빼고 "찾지 못했어요" |
다른 근거로 찾은 후보가 50m 안에 있으면 +0.15. 0.80 이상 + 후보 1개면 자동 확정. (기획서는 30m지만 실내 GPS 오차 때문에 50m)

브랜드 로고: 기본은 각 브랜드 공식 사이트 아이콘을 화면에서 바로 불러온다(`seed.py`의 `SITES`, 폰·PC가 인터넷에 연결돼 있어야 함). 더 선명한 로고를 쓰고 싶으면 `backend/logos/`에 브랜드 이름 그대로 파일을 넣으면 그 파일이 우선(예: `CGV.png`, `스타벅스.png`; png·jpg·jpeg·webp·svg). 둘 다 없으면 이니셜 배지.

근처 매장은 두 곳에서 찾는다 (사진 분석과 동시에 검색)
- **카카오 로컬 API** (`backend/.env`의 `KAKAO_REST_API_KEY`): 반경 50m 안 카페·음식점·편의점·대형마트·영화관. 프랜차이즈(`스타벅스 상암DMC점`)는 등록 브랜드로 연결, 처음 보는 동네 가게는 카카오 업종 그대로 자동 등록 → 업종 혜택으로 추천 (직접 검색 목록에는 안 나옴). 키가 없거나 호출이 실패하면 건너뜀
- **seed.py 시연용 좌표** (카카오 키가 없을 때만): 카페 오로르 4m · 버거킹 20m · 스타벅스 120m (`VITE_DEMO_GPS=37.56650,126.97800` 기준). 키가 있으면 가짜 매장이 실제 결과와 섞이지 않게 쓰지 않음

카카오 키: https://developers.kakao.com → 내 애플리케이션 → 앱 추가 → 앱 키의 **REST API 키** (카카오맵 사용 설정 안내가 나오면 켜기).
GPS 시연: `frontend/.env`의 `VITE_DEMO_GPS`가 있으면 그 좌표, 지우면 폰의 실제 GPS(https에서만 동작).

애매한 사진은 Claude가 판단 (`backend/app/ai_pick.py`, 모델 `claude-opus-5-5`)
- `backend/.env`의 `ANTHROPIC_API_KEY`. 없거나 호출이 실패하면 건너뛰고 규칙 결과 그대로
- 로고·간판으로 확실하면(0.80 이상) 부르지 않음 → 비용 0. 애매한 사진 1장당 약 15~20원, 2~5초
- 키는 console.anthropic.com (Claude Max·Team 구독이면 claude.ai 결제 설정 → API credits로 월 크레딧 연결 가능)

촬영: 앱 카메라로 찍으면 화면의 **네모 틀 영역(+사방 15%)만 잘라서** 보낸다. 틀 밖 배경(노트북 화면 등)에 인식이 끌려가지 않게. 앨범·기본 카메라 앱 사진은 전체.

폰 데이터(LTE/5G)로 테스트: 개발 PC를 임시 공개 주소로 연다 (테스트 끝나면 꼭 끌 것 — 주소를 아는 누구나 접속해 API 한도를 쓸 수 있음)
```
"C:\Program Files (x86)\cloudflared\cloudflared.exe" tunnel --url https://localhost:5173 --no-tls-verify
```
출력의 `https://○○.trycloudflare.com` 으로 접속 (`vite.config.js`의 `allowedHosts`에 허용돼 있음).

## API
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/recognitions` (multipart `image`, 선택 `lat`·`lng`) | 브랜드 후보 + 신뢰도 + 근거. `auto_confirm=true`면 바로 추천 화면 |
| GET | `/brands` | 인식 실패 시 직접 검색/선택용 목록 |
| GET | `/recommendations?brand_id=&amount=&mydata=&hour=` | 카드별 할인액·최종 결제금액·실적·남은 한도, 추천 순 정렬, `best_card_id`, `best_reason`. `hour` 비우면 지금(한국 시간) |
| GET | `/cards?mydata=` | 내 카드 실적·한도 (카드번호는 마스킹된 값만) |
| GET | `/cards/{id}/detail?mydata=` | 내 카드 상세: 카드 상태 + 이번 달 남은 혜택(혜택별 월·영역 한도·횟수) + 이번 달 결제 기록 |
| GET | `/benefits/by-category?mydata=` | 혜택별 모아보기: 업종마다 내 카드들의 남은 혜택 (받을 수 있는 것·비율 높은 순) |
| POST | `/selections` | 우리카드 결제 반영(우리페이·실물 카드) → 실적·사용 한도·월 사용 횟수 갱신, 바뀐 카드 상태 반환. 타사 카드는 거절 |
| POST | `/mydata/refresh` | 마이데이터 새로고침: 타사 카드 승인내역 반영 (시연에선 앱이 기억한 실물 카드 결제를 보냄). 실적·할인은 추정 |
| POST | `/demo/reset` | 시연 데이터 처음으로 (실적·한도·결제 기록·자동 등록 가게 초기화, 인식 기록은 남김). 내 카드 화면 맨 아래 버튼 |

추천 엔진 (기획서 3.1, `app/engine.py`)
- 가게에 걸린 혜택 찾기: 지정 브랜드 혜택은 브랜드로, 업종 혜택은 업종코드로, 전 가맹점 혜택은 항상. 매장 결제 혜택만(온라인·간편결제·해외·자동납부 제외)
- 조건 확인: 혜택별 전월실적, 시간대(자정 넘김 포함), 요일, 최소 결제금액, 월 횟수, 하루 1회 → 하나라도 아니면 할인 0원 + 이유 표시
- 할인액 = `min(정액 또는 금액 × 할인율, 건당 한도, 혜택별 월 한도 남은 것, 영역(통합) 한도 남은 것)`. 구간별 적립률·금액별 할인율도 지원
- 영역 한도: 카드의 `limit_groups`(예: 신한 Time/Daily/Monthly Plan) → 없으면 구간 월 한도 → 없으면 그 영역 혜택들의 월 한도
- 이번 달 사용 한도·횟수는 결제 기록(`selections`)으로 계산 (페르소나의 이번 달 사용 내역도 결제 기록으로 시드)
- 정렬: ① 최종 결제금액 오름차순 ② 이번 달 실적까지 남은 금액 내림차순 ③ 우리카드 우선
- 실적 코칭(`coach`): '1원 더 쓸 때 지키는 다음 달 혜택'(걸린 혜택 ÷ 남은 실적)이 1등 카드의 2배 이상이고, 양보하는 할인이 걸린 혜택의 10%(월말 7일 이하면 20%) 이하면 대안으로 제안
- 카드 상태의 `at_stake`(이번 달 실적을 못 채우면 다음 달 덜 받는 한도), `days_left`, `daily_needed` → 홈·내 카드의 월말 경고
- amount 미입력 시 10,000원 기준

마이데이터 (`mydata=false`가 기본)
- 우리카드는 자사 고객 정보라 보유 카드·지난달·이번 달 실적·한도를 항상 안다
- 타사 카드는 **보유 사실조차 모른다** → 연동 전 추천·내 카드 화면에는 우리카드만 나온다
- 연동하면 신한카드가 실적 구간·남은 한도와 함께 목록에 생기고, 모든 카드로 다시 비교한다
- 프론트의 '연동하기'는 목업(이 기기 localStorage에만 기억)
- 결제: 우리카드는 우리페이 또는 실물 카드 → 자사 승인 데이터로 바로 반영. 타사 카드는 우리페이 결제 불가(오픈페이 미지원) → 계산대에서 실물 카드로 결제 후 내 카드에서 그 카드를 골라 **마이데이터 새로고침**으로 승인내역을 받아 반영(`POST /mydata/refresh`). 승인 기준이라 실적·할인은 '추정'으로 표시
- 시연에선 추천 화면에서 타사 카드를 고른 채 나가면 그 결제를 기억해 두었다가 새로고침 때 승인내역처럼 보낸다

결제 금액 입력은 선택이다. 안 넣으면 1천~20만 원을 1천 원 단위로 미리 계산해 **금액 구간별 1등 카드**로 안내한다 (예: 올리브영 "SHOPPING+로 결제하세요 · 4만 원 넘게 결제하면 신한카드 처음이 더 아껴요", `/recommendations`의 `ranges`·`ranges_tip`). 위 표의 금액은 '결제 금액을 알면 정확히 계산해요'를 눌러 넣은 경우.

코칭은 '1원 쓸 때 지키는 다음 달 혜택'(걸린 혜택 ÷ 남은 실적)이 1등 카드의 2배 이상이고, 양보하는 할인이 걸린 혜택의 10%(월말 7일 이내는 20%) 이하일 때만 뜬다.
시연을 다시 하려면 내 카드 화면 맨 아래 '시연 데이터 처음으로'.

카드 정보: 우리카드는 자사 원장, 타사 카드는 마이데이터에서 불러온다(사용자가 카드번호를 입력·촬영하는 단계 없음). 카드번호는 끝 4자리만 보관, 화면에는 `**** **** **** 1234`로 표기.
